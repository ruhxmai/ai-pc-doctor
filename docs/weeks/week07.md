# Неделя 7. Продукционная система, прямой вывод

## Задание
Создать продукционную систему. Сформировать базу правил. Реализовать прямой вывод.

## База правил — [`data/production_rules.json`](../../data/production_rules.json)
31 продукция вида **ЕСЛИ условия ТО факты**. Условия задаются тремя списками:
`all` — все факты есть в рабочей памяти (И), `any` — хотя бы один (ИЛИ), `none` — ни одного (НЕ).

Правила образуют многоуровневую цепочку вывода:

| Группа | Приоритет | Пример |
|---|---|---|
| S — безопасность | 100 | ЕСЛИ burning_smell ТО flag:danger |
| R1 — срочный совет | 90 | ЕСЛИ flag:danger ТО advice:unplug |
| A — признаки → зона проблемы | 40 | ЕСЛИ no_power ТО area:power |
| D — зона → диагноз | 30 | ЕСЛИ area:power И (fans_not_spin ИЛИ burning_smell ИЛИ random_reboots) ТО diag:psu_failure |
| H — диагноз → тип, флаги | 20 | ЕСЛИ diag:disk_failure ИЛИ diag:malware ИЛИ … ТО flag:backup_data |
| R — рекомендации | 10 | ЕСЛИ type:hardware И НЕ type:software ТО advice:service |
| R5 — «по умолчанию» | −100 | ЕСЛИ нет ни одного diag:* ТО advice:need_more_info |

## Машина вывода — `pcdoctor/production.py`
Цикл «распознавание — действие»:
1. **Сопоставление**: все правила, условия которых выполнены и которые добавят новые факты, образуют
   конфликтное множество (агенду).
2. **Разрешение конфликта** — стратегии: `priority` (приоритет → специфичность → порядок),
   `specificity`, `recency` (правило, сопоставившееся с самыми свежими фактами), `order`.
3. **Срабатывание**: факты из части ТО добавляются в рабочую память. Правило срабатывает
   только один раз (рефрактерность).
4. Повтор, пока агенда не пуста.

Приоритеты упорядочивают уровни вывода: сначала выводятся все зоны, затем все диагнозы,
и только потом советы. Это важно для правил с НЕ: совет «в сервисный центр» (`НЕ type:software`)
не должен сработать раньше, чем будет выведен программный диагноз.

Объяснение: `InferenceResult.trace()` выдаёт полную трассировку, а `why(fact)` — цепочку правил,
которая привела к факту.

## Пример трассировки
```
Цикл 1. Агенда: {S1, A1, R5} → срабатывает S1 «Опасность возгорания»
   + flag:danger
Цикл 2. Агенда: {A1, R1, R5} → срабатывает R1 «Совет: отключить от сети»
   + advice:unplug
Цикл 3. Агенда: {A1, R5} → срабатывает A1 «Зона: питание»
   + area:power
Цикл 4. Агенда: {D1, R5} → срабатывает D1 «Диагноз: блок питания»
   + diag:psu_failure
...
```
